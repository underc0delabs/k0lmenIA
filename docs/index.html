Introducción

Qué es k0lmenIA

Un equipo de agentes especializados en QA para Claude Code, pensado para profesionales de testing manual: no hace falta programar, se trabaja conversando dentro de VS Code.

Ponés un insumo (una historia, una observación de bug, un contrato de API, o directamente una key de Jira o un link de Figma), pedís lo que necesitás en lenguaje natural y el agente que corresponde genera el resultado: análisis, planes, casos en Excel o Gherkin, datos, bugs, reportes HTML, automatización y carga en la herramienta de gestión.

1 · Diseño

Analizar historias, planificar, escribir y revisar casos manuales, BDD y de API (con su tiempo estimado), generar datos y charters, y redactar bugs.

Principios

PrincipioEn la práctica
No inventarSi falta un paso, un dato, una regla o un umbral, el agente lo marca y lo pregunta. Mejor un artefacto con huecos señalados que uno completo pero inventado.
Respetar los formatosLos campos, su orden y sus valores los definen las plantillas y los scripts, no el agente.
TrazabilidadTodo referencia la historia (HU-XXX); cada escenario automatizado lleva el ID del caso (@CP-001) y la key de la herramienta de gestión.
Cobertura pensadaPositivos, negativos, bordes y validaciones de campos, no solo el camino feliz.
Investigar antes de suponerAntes de trabajar una historia se revisan la documentación del proyecto (repositorio, PRs, mapa de la web), sus comentarios, subtareas, épica, issues vinculados, Confluence y Figma. Lo que no aparece queda marcado como Falta información (FI-01).
Ahorro de tokensLo que se repite se automatiza una vez y después corre sin agentes.
SeguridadLos secretos viven en el .env de la raíz, que nunca se versiona; los agentes nunca piden tokens por el chat.
Dos idiomasCada informe sale en español y en inglés, con una banderita para elegir cuál mandar.
Donde trabajesClonando este repo o instalándolo como plugin de Claude Code en la carpeta de cualquier proyecto: las actualizaciones llegan sin tocar tu trabajo.

Los agentes investigan el contexto completo y marcan lo que falta (FI-01).

  3. Revisá el resultadoEn output/ o en herramientas/k0lmena/.
  4. Automatizá lo que se repiteY corrélo con npm test todas las veces que quieras, sin tokens.

Falta información (FI-XX)

Cada dato que no aparece en ninguna fuente (o aparece contradictorio) recibe un ID por historia, con qué falta, dónde se buscó, a qué afecta y la pregunta para el PO. Cómo se calcula el tiempo estimado

Cada caso (manual o BDD) lleva el tiempo que tarda una persona que conoce la aplicación en ejecutarlo de punta a punta. Lo calcula scripts/estimacion.py y aparece en la planilla (columna Tiempo estimado (min) con el total), en el .md, en la herramienta de gestión, en la selección de casos y en esta revisión.

tiempo del caso = (preparación + Σ pasos + registro) × factor   # hacia arriba a 0,5 min, mínimo 1
tiempo del paso = acción + datos + verificación
ParteCómo se calcula
AcciónSegún el verbo: navegar 0,5 · clic 0,25 · completar 0,3 por campo · iniciar sesión 1 · subir o bajar un archivo 1 · esperar un correo o un proceso 2 · consultar una base, una API o logs 2 · leer 0,5 · otra 0,5 min.
Datos0,15 min por cada dato extra del paso.
Verificación0,5 min si hay resultado esperado (o es un Then) + 0,25 por cada verificación extra (hasta 4).
Preparación1 min + 0,5 por precondición (hasta 3) + 2 si hay que crear datos o usuarios.
Registro0,5 min + 0,1 por paso (marcar el resultado y guardar la evidencia).
Factor1,1 para casos negativos o de borde; ESTIMACION_FACTOR del .env multiplica todo (por ejemplo 1,3 para alguien que recién conoce la aplicación).
i

Problemas frecuentes

¿Qué pasa si a la historia le falta información?
Los agentes primero la buscan en los comentarios, subtareas, épica, issues vinculados, Confluence y Figma. Lo que no encuentran queda como Falta información (FI-01) con la pregunta para el PO, y se marca en los casos, los .feature y todos los reportes. Nunca se completa con lo que hace la app.
No sé qué me falta instalar o configurar
Corré npm run doctor: revisa por secciones Python, Node, k0lmena, Playwright, Newman, Java, Docker, las fuentes, el .env (también que cada integración esté completa y coherente, sin mostrar secretos), los conectores habilitados, git y lo que necesitan el portal, el monitoreo y los evals, y dice cómo resolver lo que falta. Con --seccion revisa solo una parte y con --rapido saltea lo lento.
La app detecta bots y frena a Playwright o a los agentes
k0lmenIA no intenta esquivar la protección (Cloudflare, Akamai, DataDome, captcha…). Cuando la app frena al navegador, el escenario queda Bloqueado: anti-bots y no Fallido, también en la herramienta de gestión, y los agentes frenan y lo reportan. La salida estable es una excepción para QA que da el equipo de la app: con QA_BYPASS_HEADER y QA_BYPASS_TOKEN en el .env, el header se manda solo a los hosts de la app. También sirven una lista blanca de IP o las claves de prueba del captcha. Mientras tanto, npm run login abre tu Chrome para resolverlo a mano, y NAVEGADOR_CANAL=chrome usa el Chrome instalado. Guía para el equipo de la app: herramientas/k0lmena/tools/navegador/README.md.
Si instalo el plugin, ¿pierdo mis cambios cuando se actualiza?
No. El plugin vive en la caché de Claude Code y tu proyecto queda aparte: input/, output/, .env y herramientas/k0lmena/ con tus pruebas no se tocan. El núcleo de k0lmena se actualiza a pedido con k0lmenia actualizar, que no toca tus features/, steps/ ni locators/. Si personalizaste un agente, hacelo con una copia en .claude/agents/ de tu proyecto, nunca editando la caché.
Un informe abre en inglés y lo quiero en español (o al revés)
Tocá la banderita de arriba a la derecha: pasa a la otra versión y recuerda la elección para el portal y los demás informes. Las dos versiones están siempre en es/ y en/, al lado del acceso.
El link para descargar el PDF da error
Los PDF ya no se versionan: los publica el workflow documentacion.yml en el release docs cuando cambia docs/. Si todavía no corrió, se lanza desde GitHub → Actions → Documentación en PDF → Run workflow. En tu PC: node docs/generar.js.
Un agente devuelve "Necesito que confirmes"
Es a propósito: los agentes corren como subagentes y no pueden preguntarte a mitad del trabajo. Respondé las preguntas y Claude continúa al mismo agente con tus respuestas.
Un agente nuevo no aparece
Reiniciá Claude Code: los agentes se cargan al iniciar la sesión.
La suite web falla sin URL o los clics dicen "outside of the viewport"
Sin URL: falta el .env de la raíz (cp .env.example .env) o BASEURL/APP_URL. Lo del viewport ya está corregido: si VIEWPORT_WIDTH y VIEWPORT_HEIGHT están vacíos, la ventana usa 1366x768. Si un test falla porque cambió un locator, pedile al reparador-automatizacion que lo arregle.
npm test corre 0 escenarios
Todavía no automatizaste nada (las carpetas vienen vacías) o el filtro TAGS no coincide con ningún escenario.
Un escenario nunca se ejecuta
Tiene el tag @bloqueado: el mapper no pudo verificar un paso. El motivo está en un comentario arriba del escenario.
"No encuentro k6"
Corré npm run bootstrap:k6 en herramientas/k0lmena/ o instalá k6 en el PATH.
"No encuentro JMeter" o "JMeter necesita Java"
Corré npm run bootstrap:jmeter (o definí JMETER_HOME) e instalá Java 8 o superior en el PATH (o definí JAVA_HOME).
npm run perf no corre un perfil con carga desde el agente
Es a propósito: fuera de una terminal interactiva hace falta --confirmar, que el agente agrega solo después de tu confirmación.
Una carpeta de Xray/QMetry/AIO aparece como C:/Program Files/Git/…
En Git Bash escribí las carpetas sin / inicial: "HU-001 Registro".
Un conector MCP no conecta
Las variables tienen que estar en el entorno donde lanzás claude (no en el .env). Atlassian y Figma se autorizan desde /mcp.
¿Los tests verifican la base de datos siempre?
No. Las verificaciones de base de datos se agregan a un .feature solo cuando las pedís, y sin DB_CONEXIONES en el .env la suite corre igual que siempre.

La descripción es lo que usa Claude Code para decidir cuándo invocarlo y se carga en cada sesión: una o dos frases (máximo 400 caracteres) con qué hace, cómo se lo pide y en qué se diferencia del agente más parecido.
