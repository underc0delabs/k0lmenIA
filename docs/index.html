Introducción

Qué es K0lmenIA Light

Un equipo de agentes especializados en QA para Claude Code, pensado para profesionales de testing manual: no hace falta programar, se trabaja conversando dentro de VS Code. Es la versión gratuita de K0lmenIA, con licencia MIT.

Ponés un insumo (una historia, una observación de bug, un contrato de API o directamente una key de Jira), pedís lo que necesitás en lenguaje natural y el agente que corresponde genera el resultado: análisis, casos, ejecuciones con evidencia o la automatización en k0lmena.

◆

1 · Diseño

Analizar historias, escribir y revisar casos manuales y BDD (con su tiempo estimado) y triar los bugs antes de cargarlos.

Queda en output/
▶

2 · Ejecución y automatización

Ejecutar en el navegador o contra una API, acompañar la ejecución manual y automatizar una sola vez: después corre con npm test, sin tokens.

Queda en output/ y herramientas/k0lmena/
⇄

3 · Gestión

Casos, ciclos y resultados con evidencias en Xray (Cloud o Server/DC) o k0lmenaTMT.

Queda en la herramienta y en output/gestion/

Principios

PrincipioEn la práctica
No inventarSi falta un paso, un dato o una regla, el agente lo marca y lo pregunta. Mejor un artefacto con huecos señalados que uno completo pero inventado.
Respetar los formatosLos campos, su orden y sus valores los definen las plantillas y los scripts, no el agente.
TrazabilidadTodo referencia la historia (HU-XXX); cada escenario automatizado lleva el ID del caso (@CP-001) y la key de la herramienta de gestión.
Cobertura pensadaPositivos, negativos, bordes y validaciones de campos, no solo el camino feliz.
Investigar antes de suponerAntes de trabajar una historia se revisan la documentación del proyecto (repositorio y mapa de la web), sus comentarios, subtareas, épica e issues vinculados. Lo que no aparece queda como Falta información.
Ahorro de tokensLo que se repite se automatiza una vez y después corre sin agentes.
SeguridadLos secretos viven en el .env de la raíz, que nunca se versiona; los agentes nunca piden tokens por el chat.
Dos idiomasCada informe sale en español y en inglés, con una banderita para elegir cuál mandar.
Donde trabajesComo plugin de Claude Code en la carpeta de cualquier proyecto o clonando este repo: las actualizaciones llegan sin tocar tu trabajo.

Primeros pasos

Instalación

La forma más fácil es el plugin (ver la sección siguiente). Si preferís clonar el repo:

# 1. Claude Code (macOS / Linux; en Windows seguí la guía oficial)
curl -fsSL https://claude.ai/install.sh | bash

# 2. El repositorio
git clone https://github.com/underc0delabs/k0lmenIA.git
cd k0lmenIA
pip install -r requirements.txt   # en Mac/Linux: pip3 install -r requirements.txt
npm install                       # k0lmena (se instala en herramientas/k0lmena)
npm run configurar                # tu app y tus herramientas: crea el .env y activa los conectores

# 3. Revisá que esté todo listo
npm run doctor

# 4. A trabajar
code .
claude
i

En Windows el comando de Python es python; en Mac y Linux, python3 y pip3. Para la ejecución E2E en vivo: npx playwright install; para colecciones de Postman: npm install -g newman.

Primeros pasos

Como plugin de Claude Code

Se instala como plugin y funciona en la carpeta de cualquier proyecto, sin clonar este repo. Las actualizaciones llegan solas y nunca tocan tu trabajo.

claude plugin marketplace add underc0delabs/k0lmenIA
claude plugin install k0lmenia@k0lmenia
  1. Abrí Claude Code en la carpeta de tu proyectoY escribí /k0lmenia:empezar: prepara el proyecto (carpetas, .env y k0lmena), revisa que tengas todo instalado, te ayuda a conectar Jira y te propone la primera tarea.
  2. Pedí lo que necesitesEn lenguaje natural: "Escribí los casos de prueba de PROJ-12", "Probá el login en el navegador".
TemaCómo funciona
ComandosLo que en el repo es npm run <x>, en el plugin es k0lmenia <x> (k0lmenia ayuda los lista). Los agentes se llaman k0lmenia:<agente>.
Qué instala y dóndeEl código queda en la caché de Claude Code y se actualiza solo. k0lmenia init deja en tu proyecto input/, output/, el .env, TAREAS.md, tu copia de k0lmena y los mismos permisos que el repo. Nunca pisa un archivo que ya existe.
ActualizarCada push a main se publica en la rama plugin. Activá la actualización automática (/plugin → Marketplaces → k0lmenia) o corré /plugin marketplace update k0lmenia.
NovedadesDespués de una actualización, Claude te cuenta al iniciar la sesión qué cambió; a pedido, k0lmenia novedades (con el repo, npm run novedades).
Actualizar k0lmenak0lmenia actualizar: tus pruebas no se tocan; si modificaste un archivo del framework, la versión nueva queda al lado como .nuevo.

Documentación del proyecto

El documentador-proyecto junta el contexto real del proyecto en input/documentacion/, para que los demás agentes trabajen sobre lo que existe y no sobre suposiciones.

Documentá el proyecto.
Juntá todo el contexto de PROJ-12 antes de escribir los casos.
FuenteQué lee
Repositorio de la appEl clon local (REPO_RUTA_LOCAL): README y docs, validaciones y límites, mensajes, estados, roles y permisos, rutas y contratos de API (solo lectura).
HistoriasJira con todos sus comentarios, subtareas, épica, vínculos y bugs.
La aplicaciónnpm run mapa-funcional: páginas, menús, formularios con cada campo, botones y mensajes (solo GET, sin enviar nada).

Deja una base del proyecto, un dossier por historia y un índice (INDICE.md), cada dato con su fuente. Es incremental: "Actualizá la documentación" rehace solo lo que cambió, y npm run actualizar-conocimiento lo puede correr programado.

Guías

Investigación de contexto y "Falta información"

Antes de analizar, escribir casos o automatizar una historia, los agentes investigan su contexto completo (skill investigacion-contexto) en lugar de suponer.

FuenteQué revisan
Documentación del proyectoPrimero: el índice y el dossier de la historia en input/documentacion/.
Historia de JiraDescripción, criterios, estado, labels, componentes y adjuntos.
ComentariosTodos: las decisiones que se tomaron después reemplazan a la descripción.
Subtareas, épica e issues vinculadosReglas generales, historias hermanas y bugs conocidos del flujo.
Contratos e input/Swagger, Postman y documentación local.

Lo que no aparece en ninguna fuente se marca como Falta información con un ID por historia (FI-01, FI-02, …) que viaja a la planilla de casos, los .feature (@falta-info @FI-01), las coberturas, los mapeos, los reportes de ejecución y lo que se publica en Xray o k0lmenaTMT.

Automatización con k0lmena

k0lmena vive en herramientas/k0lmena/. Los agentes mapper verifican tus casos contra la app real y escriben la automatización una sola vez; después la suite corre las veces que quieras, sin tokens.

npm test                          # web + API
npm run test:web                  # también: test:api · test:all
TAGS=@HU-001 npm test             # filtrar por tag
npm run report:web                # regenera el reporte HTML (también: report:api)
SuiteTest que pasaTest que falla
WebCaptura final (+ GIF opcional)Video completo, captura, error, logs del navegador y de Node, trace de Playwright
APIRequest y response (Authorization oculto)Lo mismo + la validación que falló

npm run login guarda una sesión iniciada a mano (captcha, 2FA, SSO) para que npm test y el navegador de los agentes arranquen logueados. También: npm run mapa-funcional, npm run record, npm run record:generator, npm run debug y auto-healing de locators. Detalle en herramientas/k0lmena/README.md.

Guías

Gestión de pruebas: Xray y k0lmenaTMT

Configurá GESTION_HERRAMIENTA (xray-cloud · xray-dc · k0lmena-tmt), GESTION_PROYECTO y las credenciales en el .env.

Subí los casos de HU-001 a Xray en la carpeta 'HU-001 Registro', vinculados a PROJ-12, y creá el ciclo Sprint 5.
Subí los resultados de la última corrida al ciclo PROJ-60.

El gestor-pruebas crea carpetas, casos, vínculos y ciclos (y con sincronizar-casos pone al día los que cambiaron); el publicador-resultados carga estado, error y evidencias. Sirve para k0lmena y para cualquier framework que genere JUnit XML. La trazabilidad (output/gestion/<HU>-<herramienta>.json) evita duplicados.

k0lmenaTMT

Se integra con el token personal (K0LMENA_TMT_TOKEN). Las cargas las hace scripts/gestion por su server MCP, sin pasar cada caso por la conversación; el conector k0lmena-tmt queda para consultar desde el chat. Keys: TC-<id> (casos) y CY-<id> (ciclos).

Guías

k0lmena en el pipeline (CI)

Las suites de k0lmena corren solas en el pipeline del equipo, sin agentes ni tokens.

npm run ci -- generar --plataforma github                # → .github/workflows/k0lmena.yml
npm run ci -- generar --plataforma gitlab --suite all    # → .gitlab-ci.yml
npm run ci -- generar --plataforma jenkins               # → Jenkinsfile
npm run ci -- generar --plataforma azure --suite api     # → azure-pipelines.yml

El pipeline instala k0lmena y Chromium, corre las suites y guarda los reportes como artefacto; con GESTION_CICLO publica los resultados en Xray o k0lmenaTMT. El .env va entero como secret del pipeline. Detalle en herramientas/ci/README.md.

Triage de bugs

¿BUG-008 ya está cargado en Jira?

El triador-bugs busca si el bug ya existe en Jira o en los bugs locales, detecta regresiones de bugs cerrados y sugiere severidad, prioridad, componente, responsable e historia. Crear o vincular en Jira, solo con tu confirmación.

Ejecución manual acompañada

Con el skill ejecucion-manual la conversación te guía por los casos manuales: un caso y un paso por vez, el resultado, la evidencia, el tiempo real contra el estimado y el bug redactado en el momento si algo falla.

/k0lmenia:ejecucion-manual HU-012                # en Claude Code
npm run ejecucion-manual -- estado --sesion output/ejecucion-manual/HU-012

La sesión queda en output/ejecucion-manual/<HU>/sesion.json, así que se pausa y se retoma otro día. Al cerrar, el asistente-ejecucion-manual arma el informe (ES/EN) y avisa las inconsistencias; publicar en Xray o k0lmenaTMT, solo con confirmación.

Historial de corridas

Cada corrida de npm test guarda sus últimas 5 corridas con su evidencia en herramientas/k0lmena/reports/<suite>/historial/, y cada informe trae la sección Evolución de las corridas: qué es nuevo, qué se resolvió y cómo evolucionan los indicadores.

Evals de los agentes

Los evals (evals/) miden la calidad de lo que generan los agentes: cada caso trae trampas deliberadas (ambigüedades, contradicciones, límites, secretos) y chequeos determinísticos. Corren en un workspace aislado con claude -p y dejan un informe con las regresiones contra la corrida anterior.

npm run evals -- --listar
npm run evals -- --correr --agente generador-casos-manuales
i

Gastan tokens: cada caso es una conversación completa, con un tope por caso. --referencia y --solo-verificar revisan sin correr el agente.

Problemas frecuentes

¿Qué pasa si a la historia le falta información?
Los agentes primero la buscan en los comentarios, subtareas, épica e issues vinculados. Lo que no encuentran queda como Falta información (FI-01) con la pregunta para el PO, y viaja a todos los artefactos.
No sé qué me falta instalar o configurar
Corré npm run doctor: revisa Python, Node, k0lmena, Playwright, Newman, las fuentes, el .env, las integraciones, los conectores y git, y dice cómo resolver cada cosa.
Un agente nuevo no aparece
Reiniciá Claude Code.
npm test corre 0 escenarios
Todavía no automatizaste nada o TAGS no coincide.
Un escenario nunca se ejecuta
Tiene @bloqueado: el motivo está en un comentario arriba.
Un agente devuelve "Necesito que confirmes"
Es a propósito: los agentes no pueden preguntar a mitad del trabajo. Respondé y Claude lo continúa.
Un conector MCP no conecta
Corré npm run doctor: dice qué variable falta en el .env. Atlassian se autoriza desde /mcp.

Extender el proyecto

  1. Creá el archivo.claude/agents/mi-agente.md con frontmatter name y description. La descripción es lo que usa Claude Code para decidir cuándo invocarlo.
  2. Escribí el cuerpoEn español: rol, entradas, proceso, salida y reglas.
  3. Definí el formatoSi genera un formato propio, sumá su plantilla en plantillas/ o su script en scripts/, y su carpeta en output/.
  4. Informe en dos idiomasSi arma un informe HTML, escribilo con escribir_bilingue y localizar (scripts/_i18n.py).

Regenerar esta documentación

node docs/generar.js        # diagramas (PNG) y PDF en los dos idiomas

El sitio es docs/index.html (publicado con GitHub Pages en underc0delabs.github.io/k0lmenIA), con su versión en inglés en docs/en/index.html. Los PDF los publica el workflow documentacion.yml en el release docs.
