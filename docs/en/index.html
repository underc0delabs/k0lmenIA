Introduction

What K0lmenIA Light is

A team of QA-specialized agents for Claude Code, built for manual testers: no coding needed, you work by talking to Claude inside VS Code. It is the free edition of K0lmenIA, under the MIT license.

You provide an input (a story, a bug observation, an API contract or just a Jira key), ask for what you need in plain language, and the right agent produces the result: analysis, test cases, runs with evidence or the k0lmena automation. The agents work in Spanish.

◆

1 · Design

Analyze stories, write and review manual and BDD test cases (with their estimated time) and triage bugs before filing them.

Saved in output/
▶

2 · Execution and automation

Run in the browser or against an API, guide manual execution and automate once: then it runs with npm test, with no tokens.

Saved in output/ and herramientas/k0lmena/
⇄

3 · Test management

Test cases, cycles and results with evidence in Xray (Cloud or Server/DC) or k0lmenaTMT.

Saved in the tool and in output/gestion/

Principles

PrincipleIn practice
Don't make things upIf a step, a piece of data or a rule is missing, the agent flags it and asks. Better an artifact with marked gaps than a complete but invented one.
Respect the formatsFields, their order and their values are defined by the templates and scripts, not by the agent.
TraceabilityEverything references the story (HU-XXX); each automated scenario carries the case ID (@CP-001) and the test management key.
Thoughtful coveragePositive, negative, edge cases and field validations, not just the happy path.
Research before assumingBefore working on a story, the agents review the project documentation (repository and web map), its comments, subtasks, epic and linked issues. Whatever is not found becomes Missing information.
Token savingsWhat repeats is automated once and then runs without agents.
SecuritySecrets live in the root .env, which is never versioned; agents never ask for tokens in the chat.
Two languagesEvery report comes out in Spanish and English, with a flag to choose which one to send.
Wherever you workAs a Claude Code plugin in any project folder or by cloning this repo: updates arrive without touching your work.

How it is used

  1. Provide your inputsAsk "Documentá el proyecto" (document the project) to gather the context of the repository, the stories and the web in input/documentacion/; put everything else in input/, or pass a Jira key.
  2. Ask in plain languageClaude Code picks the agent. You can also name it: "use the web-mapper to…".
  3. Review the resultIn output/ or in herramientas/k0lmena/.
  4. Automate what repeatsAnd run it with npm test as many times as you want, with no tokens.
i

Task list. To hand over several things at once, write one task per line in TAREAS.md (in the root), with its checkbox, and ask "Hacé las tareas de TAREAS.md". Claude asks everything it needs up front, does them in order and marks each one.

Getting started

Installation

The easiest way is the plugin (see the next section). If you prefer to clone the repo:

# 1. Claude Code (macOS / Linux; on Windows follow the official guide)
curl -fsSL https://claude.ai/install.sh | bash

# 2. The repository
git clone https://github.com/underc0delabs/k0lmenIA.git
cd k0lmenIA
pip install -r requirements.txt   # on Mac/Linux: pip3 install -r requirements.txt
npm install                       # k0lmena (installed in herramientas/k0lmena)
npm run configurar                # your app and your tools: creates the .env and enables the connectors

# 3. Check that everything is ready
npm run doctor

# 4. Get to work
code .
claude
i

On Windows the Python command is python; on Mac and Linux, python3 and pip3. For live E2E runs: npx playwright install; for Postman collections: npm install -g newman.

Getting started

As a Claude Code plugin

It installs as a plugin and works in any project folder, without cloning this repo. Updates arrive automatically and never touch your work.

claude plugin marketplace add underc0delabs/k0lmenIA
claude plugin install k0lmenia@k0lmenia
  1. Open Claude Code in your project folderAnd type /k0lmenia:empezar: it prepares the project (folders, .env and k0lmena), checks that everything is installed, helps you connect Jira and suggests the first task.
  2. Ask for what you needIn plain language: "Write the test cases for PROJ-12", "Test the login in the browser".
TopicHow it works
CommandsWhat is npm run <x> in the repo is k0lmenia <x> in the plugin (k0lmenia ayuda lists them). Agents are called k0lmenia:<agent>.
What it installs and whereThe code stays in the Claude Code cache and updates itself. k0lmenia init leaves in your project input/, output/, the .env, TAREAS.md, your copy of k0lmena and the same permissions as the repo. It never overwrites an existing file.
UpdatingEvery push to main is published to the plugin branch. Turn on auto-update (/plugin → Marketplaces → k0lmenia) or run /plugin marketplace update k0lmenia.
What's newAfter an update, Claude tells you at the start of the session what changed; on demand, k0lmenia novedades (with the repo, npm run novedades).
Updating k0lmenak0lmenia actualizar: your tests are not touched; if you changed a framework file, the new version is left next to it as .nuevo.

Guides

Project documentation

The documentador-proyecto gathers the real project context in input/documentacion/, so the other agents work on what exists instead of assumptions.

Document the project.
Gather all the context of PROJ-12 before writing the test cases.
SourceWhat it reads
App repositoryThe local clone (REPO_RUTA_LOCAL): README and docs, validations and limits, messages, states, roles and permissions, routes and API contracts (read-only).
StoriesJira with all their comments, subtasks, epic, links and bugs.
The applicationnpm run mapa-funcional: pages, menus, forms with each field, buttons and messages (GET only, nothing is submitted).

It leaves a project base, one dossier per story and an index (INDICE.md), each fact with its source. It is incremental: asking to update the documentation redoes only what changed, and npm run actualizar-conocimiento can run it on a schedule.

Guides

Context research and "Missing information"

Before analyzing, writing test cases or automating a story, the agents research its full context (skill investigacion-contexto) instead of assuming.

SourceWhat they check
Project documentationFirst: the index and the story dossier in input/documentacion/.
Jira storyDescription, criteria, status, labels, components and attachments.
CommentsAll of them: decisions made later replace the description.
Subtasks, epic and linked issuesGeneral rules, sibling stories and known bugs in the flow.
Contracts and input/Swagger, Postman and local documentation.

Whatever is not found in any source is marked as Missing information with one ID per story (FI-01, FI-02, …) that travels to the test case sheet, the .feature files (@falta-info @FI-01), coverage reports, mappings, execution reports and what is published to Xray or k0lmenaTMT.

Guides

Automation with k0lmena

k0lmena lives in herramientas/k0lmena/. The mapper agents check your test cases against the real app and write the automation only once; after that the suite runs as many times as you want, with no tokens.

npm test                          # web + API
npm run test:web                  # also: test:api · test:all
TAGS=@HU-001 npm test             # filter by tag
npm run report:web                # rebuilds the HTML report (also: report:api)
SuitePassing testFailing test
WebFinal screenshot (+ optional GIF)Full video, screenshot, error, browser and Node logs, Playwright trace
APIRequest and response (Authorization hidden)The same + the failed validation

npm run login saves a session you log into by hand (captcha, 2FA, SSO) so npm test and the agents' browser start logged in. Also: npm run mapa-funcional, npm run record, npm run record:generator, npm run debug and locator auto-healing. Details in herramientas/k0lmena/README.md.

Guides

Test management: Xray and k0lmenaTMT

Set GESTION_HERRAMIENTA (xray-cloud · xray-dc · k0lmena-tmt), GESTION_PROYECTO and the credentials in the .env.

Upload the HU-001 cases to Xray in the 'HU-001 Registro' folder, linked to PROJ-12, and create the Sprint 5 cycle.
Upload the results of the last run to cycle PROJ-60.

The gestor-pruebas creates folders, test cases, links and cycles (and with sincronizar-casos updates the ones that changed); the publicador-resultados uploads status, error and evidence. It works for k0lmena and for any framework that produces JUnit XML. Traceability (output/gestion/<HU>-<tool>.json) prevents duplicates.

k0lmenaTMT

It integrates with the personal token (K0LMENA_TMT_TOKEN). Uploads are done by scripts/gestion through its MCP server, without passing each case through the conversation; the k0lmena-tmt connector is for queries from the chat. Keys: TC-<id> (cases) and CY-<id> (cycles).

Guides

k0lmena in the pipeline (CI)

The k0lmena suites run on their own in the team's pipeline, with no agents or tokens.

npm run ci -- generar --plataforma github                # → .github/workflows/k0lmena.yml
npm run ci -- generar --plataforma gitlab --suite all    # → .gitlab-ci.yml
npm run ci -- generar --plataforma jenkins               # → Jenkinsfile
npm run ci -- generar --plataforma azure --suite api     # → azure-pipelines.yml

The pipeline installs k0lmena and Chromium, runs the suites and keeps the reports as an artifact; with GESTION_CICLO it publishes the results to Xray or k0lmenaTMT. The whole .env goes in as a pipeline secret. Details in herramientas/ci/README.md.

Guides

Apps with anti-bot protection

If the app uses Cloudflare, Akamai, DataDome, Imperva, AWS WAF or a captcha, it may block the automated browser. K0lmenIA does not try to bypass it.

What it doesHow
No false failuresThe scenario is marked Blocked: anti-bot (also in Xray and k0lmenaTMT) and the agents stop and report it.
Bypass headerQA_BYPASS_HEADER and QA_BYPASS_TOKEN in the .env: sent only to the app's hosts.
Real Chrome and human paceNAVEGADOR_CANAL=chrome and RITMO_HUMANO=si.
Manual plan Bnpm run login: you solve the challenge by hand and the session is saved (SESION=si).

Bug triage

Is BUG-008 already filed in Jira?

The triador-bugs checks whether the bug already exists in Jira or in the local bugs, detects regressions of closed bugs and suggests severity, priority, component, owner and story. Creating or linking in Jira only happens after you confirm.

Guides

Guided manual execution

With the ejecucion-manual skill, the conversation guides you through the manual test cases: one case and one step at a time, the result, the evidence, actual vs. estimated time and the bug written on the spot if something fails.

/k0lmenia:ejecucion-manual HU-012                # in Claude Code
npm run ejecucion-manual -- estado --sesion output/ejecucion-manual/HU-012

The session is saved in output/ejecucion-manual/<HU>/sesion.json, so you can pause and resume another day. When closing, the asistente-ejecucion-manual builds the report (ES/EN) and flags inconsistencies; publishing to Xray or k0lmenaTMT only happens after confirmation.

Guides

Run history

Each npm test run keeps its last 5 runs with their evidence in herramientas/k0lmena/reports/<suite>/historial/, and each report includes a Run evolution section: what is new, what was fixed and how the indicators evolve.

Guides

Agent evals

The evals (evals/) measure the quality of what the agents produce: each case has deliberate traps (ambiguities, contradictions, limits, secrets) and deterministic checks. They run in an isolated workspace with claude -p and leave a report with regressions against the previous run.

npm run evals -- --listar
npm run evals -- --correr --agente generador-casos-manuales
i

They use tokens: each case is a full conversation, with a cap per case. --referencia and --solo-verificar check without running the agent.

Guides

Token usage

python scripts/metricas_tokens.py reads the project's Claude Code transcripts (only the counts, never the text), attributes usage to each agent and builds a report with the estimated cost per agent, day and model.

FAQ

What happens if the story is missing information?
The agents first look for it in the comments, subtasks, epic and linked issues. Whatever they don't find becomes Missing information (FI-01) with the question for the PO, and travels to every artifact.
I don't know what I'm missing to install or configure
Run npm run doctor: it checks Python, Node, k0lmena, Playwright, Newman, the fonts, the .env, the integrations, the connectors and git, and tells you how to fix each one.
A new agent doesn't show up
Restart Claude Code.
npm test runs 0 scenarios
You haven't automated anything yet or TAGS doesn't match.
A scenario never runs
It has @bloqueado: the reason is in a comment above it.
An agent returns "Necesito que confirmes" (I need you to confirm)
That's on purpose: agents can't ask questions mid-task. Answer and Claude continues.
An MCP connector doesn't connect
Run npm run doctor: it tells you which variable is missing in the .env. Atlassian is authorized from /mcp.

Extending the project

  1. Create the file.claude/agents/my-agent.md with name and description frontmatter. The description is what Claude Code uses to decide when to invoke it.
  2. Write the bodyRole, inputs, process, output and rules.
  3. Define the formatIf it produces its own format, add its template in plantillas/ or its script in scripts/, and its folder in output/.
  4. Report in two languagesIf it builds an HTML report, write it with escribir_bilingue and localizar (scripts/_i18n.py).

Rebuild this documentation

node docs/generar.js        # diagrams (PNG) and PDF in both languages

The site is docs/index.html (published with GitHub Pages at underc0delabs.github.io/k0lmenIA), with its English version in docs/en/index.html. The PDFs are published by the documentacion.yml workflow in the docs release.
