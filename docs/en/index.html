Introduction

What is k0lmenIA

A team of specialized QA agents for Claude Code, built for manual testing professionals: no programming needed, you work by talking to it inside VS Code.

You provide an input (a user story, a bug observation, an API contract, or simply a Jira key or a Figma link), ask for what you need in natural language, and the right agent produces the result: analyses, plans, test cases in Excel or Gherkin, test data, bug reports, HTML reports, automation and upload to your test management tool. The agents and their deliverables are in Spanish.

◆

1 · Design

Analyze stories, plan, write and review manual, BDD and API test cases (with their estimated time), generate data and charters, and write bug reports.

Saved in output/
▶

2 · Automation

The mapper agents write the automation once; after that it runs with npm, with no tokens.

Saved in herramientas/k0lmena/
⇄

3 · Management

Test cases, cycles and results with evidence in Xray, QMetry, AIO Tests or Zephyr (test cases also in Azure DevOps), and the closing report.

Your tool + output/

Principles

PrincipleIn practice
Don't make things upIf a step, a piece of data, a rule or a threshold is missing, the agent flags it and asks. Better an artifact with marked gaps than a complete but invented one.
Respect the formatsFields, their order and their values are defined by the templates and scripts, not by the agent.
TraceabilityEverything references the story (HU-XXX); every automated scenario carries the test case ID (@CP-001) and the key in the test management tool.
Thoughtful coveragePositive, negative, edge cases and field validations, not just the happy path.
Research before assumingBefore working on a story, the agents review the project documentation (repository, PRs, map of the web app), its comments, subtasks, epic, linked issues, Confluence and Figma. Whatever doesn't show up is marked as Missing information (FI-01).
Token savingsWhat repeats is automated once and then runs without agents.
SecuritySecrets live in the .env at the root, which is never committed; the agents never ask for tokens in the chat.
Two languagesEvery report comes in Spanish and English, with a flag to pick which one to send.
Wherever you workClone this repo or install it as a Claude Code plugin in any project folder: updates arrive without touching your work.

Introduction

How to use it

  1. Provide your inputsAsk "Documentá el proyecto" (document the project) to gather the context from the repository, the stories and the web app into input/documentacion/; put everything else in input/, or pass a Jira key, a Confluence page or a Figma link with the connector active. The agents research the full context and flag what's missing (FI-01).
  2. Ask in natural languageClaude Code picks the agent. You can also name it: "usá el web-mapper para…" (use the web-mapper to…).
  3. Review the resultIn output/ or in herramientas/k0lmena/.
  4. Automate what repeatsAnd run it with npm test as many times as you want, with no tokens.

The agents work in Spanish, so the example requests below are in Spanish, followed by their meaning.

Updating

How updates arrive

This repo is where development happens. On every push to main, the plugin.yml workflow builds the plugin (scripts/construir_plugin.py) and publishes it to the plugin branch, which is lightweight and has none of the repo's history. The plugin doesn't pin a version, so every publication is a new version: you get it with /plugin marketplace update k0lmenia, or automatically if you turned auto-update on. The previous version is deleted after 14 days.

Customizing and working as a team

  • An agent of your own: copy it to your project's .claude/agents/. That copy takes precedence over the plugin's, but it stops receiving that agent's improvements. Anything you can solve with the .env or your project's CLAUDE.md is better solved there.
  • For the whole team: declare the marketplace and the plugin in the project's .claude/settings.json. Each person installs it once and accepts the folder's trust dialog.
{
  "extraKnownMarketplaces": {"k0lmenia": {"source": {"source": "github", "repo": "underc0delabs/k0lmenIA", "ref": "plugin"}}},
  "enabledPlugins": {"k0lmenia@k0lmenia": true}
}
!

Limitations. A plugin can't ship the list of allowed commands: the first time, Claude asks for approval to run k0lmenia … (each team can add it to its .claude/settings.json). If you use the plugin and the cloned repo in the same folder, you'll see the agents twice (with and without the prefix).

If the app answers with a challenge or an access-denied page, the scenario is marked Blocked: anti-bot (also when it's published to the test management tool) and the failure analysis keeps it apart from bugs. The tools warn about it at the end and the agents stop and report it.

⇄

case time = (setup + Σ steps + logging) × factor   # rounded up to 0.5 min, minimum 1
step time = action + data + verification
PartHow it's calculated
ActionBy verb: navigate 0.5 · click 0.25 · fill in 0.3 per field · log in 1 · upload or download a file 1 · wait for an email or a process 2 · query a database, an API or logs 2 · read 0.5 · other 0.5 min.
Data0.15 min for each extra piece of data in the step.
Verification0.5 min if there's an expected result (or it's a Then) + 0.25 for each extra check (up to 4).
Setup1 min + 0.5 per precondition (up to 3) + 2 if data or users have to be created.
Logging0.5 min + 0.1 per step (marking the result and saving the evidence).
Factor1.1 for negative or edge cases; ESTIMACION_FACTOR in the .env multiplies everything (for example 1.3 for someone new to the application).

Agent evals

The tests cover the scripts; the evals measure the quality of what the agents generate.

Each case in evals/casos/ gives an agent a story, a contract, an observation or a repository with deliberate traps (ambiguities, a contradiction between description and comment, undefined messages, limits, a fake secret) and verifies with deterministic checks that it marks the Missing information, applies boundary values, respects the templates and doesn't make things up. Troubleshooting

What happens if the story is missing information?
The agents first look for it in the comments, subtasks, epic, linked issues, Confluence and Figma. Whatever they don't find is recorded as Missing information (FI-01) with the question for the PO, and it's marked in the test cases, the .feature files and every report. It's never filled in with what the app does.
I don't know what I'm missing to install or configure
Run npm run doctor: it checks, section by section, Python, Node, k0lmena, Playwright, Newman, Java, Docker, the fonts, the .env (including that each integration is complete and consistent, without showing secrets), the enabled connectors, git and what the portal, the monitoring and the evals need, and tells you how to fix what's missing. With --seccion it checks only one part and with --rapido it skips the slow checks.
The app detects bots and blocks Playwright or the agents
k0lmenIA doesn't try to get around the protection (Cloudflare, Akamai, DataDome, captcha…). When the app blocks the browser, the scenario is marked Blocked: anti-bot instead of Failed, also in the test management tool, and the agents stop and report it. The reliable fix is a QA exception from the app team: with QA_BYPASS_HEADER and QA_BYPASS_TOKEN in the .env, the header is sent only to the app's hosts. An IP allowlist or the captcha test keys also work. Meanwhile, npm run login opens your Chrome so you can solve it by hand, and NAVEGADOR_CANAL=chrome uses your installed Chrome. Guide for the app team: herramientas/k0lmena/tools/navegador/README.md.
If I install the plugin, do I lose my changes when it updates?
No. The plugin lives in Claude Code's cache and your project stays separate: input/, output/, .env and herramientas/k0lmena/ with your tests are never touched. The k0lmena core is updated on demand with k0lmenia actualizar, which doesn't touch your features/, steps/ or locators/. If you customized an agent, do it with a copy in your project's .claude/agents/, never by editing the cache.
A report opens in English and I want it in Spanish (or the other way around)
Click the flag at the top right: it switches to the other version and remembers your choice for the portal and the other reports. Both versions are always in es/ and en/, next to the entry file.
The PDF download link fails
The PDFs are no longer committed: the documentacion.yml workflow publishes them in the docs release whenever docs/ changes. If it hasn't run yet, start it from GitHub → Actions → Documentación en PDF → Run workflow. On your machine: node docs/generar.js.
An agent returns "Necesito que confirmes" (I need you to confirm)
That's on purpose: the agents run as subagents and can't ask you mid-task. Answer the questions and Claude resumes the same agent with your answers.
A new agent doesn't show up
Restart Claude Code: agents are loaded when the session starts.
The web suite fails without a URL or clicks say "outside of the viewport"
No URL: the root .env is missing (cp .env.example .env) or BASEURL/APP_URL is. The viewport issue is already fixed: if VIEWPORT_WIDTH and VIEWPORT_HEIGHT are empty, the window uses 1366x768. If a test fails because a locator changed, ask reparador-automatizacion to fix it.
npm test runs 0 scenarios
You haven't automated anything yet (the folders ship empty) or the TAGS filter doesn't match any scenario.
A scenario never runs
It has the @bloqueado tag: the mapper couldn't verify a step. The reason is in a comment above the scenario.
"No encuentro k6" (k6 not found)
Run npm run bootstrap:k6 in herramientas/k0lmena/ or install k6 on the PATH.
"No encuentro JMeter" or "JMeter necesita Java"
Run npm run bootstrap:jmeter (or set JMETER_HOME) and install Java 8 or later on the PATH (or set JAVA_HOME).
npm run perf doesn't run a load profile from the agent
That's on purpose: outside an interactive terminal it needs --confirmar, which the agent adds only after your confirmation.
An Xray/QMetry/AIO folder shows up as C:/Program Files/Git/…
In Git Bash write the folders without a leading /: "HU-001 Registro".
An MCP connector doesn't connect
The variables have to be in the environment where you launch claude (not in the .env). Atlassian and Figma are authorized from /mcp.
Do the tests always check the database?
No. Database checks are added to a .feature only when you ask, and without DB_CONEXIONES in the .env the suite runs as always.
A Python library is missing
pip install -r requirements.txt

Adding an agent

  1. Create the file.claude/agents/mi-agente.md with name and description frontmatter. The description is what Claude Code uses to decide when to invoke it, and it's loaded in every session: one or two sentences (400 characters at most) with what it does, how to ask for it and how it differs from the most similar agent.
  2. Short body, reference in a skillThe agent holds the role, the flow, the rules and the output. Criteria tables, catalogs and long formats go into a skill, which is only loaded when needed.
  3. Write the bodyIn Spanish, like the rest: role, inputs, process, output and rules.
  4. Define the formatIf it generates its own format, add its template in plantillas/ or its script in scripts/, and its folder in output/.
  5. Normalize the tablesIf it generates tables in a .md, run them through scripts/formatear_tablas.py.
  6. Report in two languagesIf it builds an HTML report, write it with escribir_bilingue and localizar (scripts/_i18n.py), add its texts to the scripts/i18n/en/ dictionary and ask the agent for the "en" block of the JSON.
